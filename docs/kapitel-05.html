Das solltest du schon kennen: Klasse, Objekt, Konstruktor, new und Getter aus Kapitel 4, Rückgabewerte aus Kapitel 3.

In Kapitel 4 hast du Klassen selbst geschrieben. Oft ist es umgekehrt: Die Klassen gibt es schon, jemand anderes hat sie geschrieben. Du bekommst eine Beschreibung und sollst die Klassen in main benutzen. Genau so ist Übung 2 in der Präsenzübung aufgebaut.

Das ist wie bei einem Fahrradverleih-Automaten. Du musst nicht wissen, wie er innen funktioniert. Du musst nur wissen, welche Knöpfe es gibt, was du eingeben musst und was herauskommt. Die Beschreibung einer Klasse ist so eine Bedienungsanleitung.

Das Thema in diesem Kapitel ist ein Verleih für E-Bikes. Es gibt drei Klassen: Bike (ein Rad), Station (der Platz, an dem Räder stehen) und Rider (eine Person, die fährt). Du lernst sie nacheinander kennen.

Eine Beschreibung lesen

So eine Beschreibung sieht zum Beispiel so aus. Lies sie einmal ganz durch:

Klasse Bike

Die Klasse Bike repräsentiert ein E-Bike mit den Attributen Nummer (number) und Akkustand in Prozent (battery). Sie besitzt die folgenden Methoden:

  • Bike(final String number, final int battery): Ein Konstruktor, um ein neues Bike-Objekt mit der gegebenen Nummer und dem gegebenen Akkustand zu erzeugen.
  • String getNumber(): Gibt die Nummer des Rads zurück.
  • int getBattery(): Gibt den Akkustand zurück.
  • void drive(final int minutes): Das Rad fährt. Der Akkustand sinkt um 1 Prozent pro Minute.
  • String getInfo(): Gibt einen Text mit der Nummer und dem Akkustand zurück.

Das Wichtigste steht in den Zeilen mit Code. Du liest sie wie einen Steckbrief. Fang mit dem Konstruktor an. Du erkennst ihn daran, dass er wie die Klasse heißt:

BikeName wie die KlasseAlso ein Konstruktor. Du benutzt ihn mit new Bike(…).
(String …, int …)Was er brauchtErst einen Text (die Nummer), dann eine Zahl (den Akkustand). Genau in dieser Reihenfolge.
finalDarfst du überlesenEs heißt nur: Der Konstruktor ändert diesen Parameter nicht. Für dich ändert sich nichts.

Der Konstruktor von Bike braucht einen Text und dann eine Zahl. Also schreibst du: new Bike("B-12", 80).

Bei den Methoden steht vorn der Rückgabetyp. Er sagt dir, was zurückkommt:

intWas zurückkommtEine Zahl. Steht hier void, kommt nichts zurück.
getBatteryDer NameGenau so schreibst du ihn, auch Groß- und Kleinbuchstaben.
()Was sie bekommtHier nichts. Die Klammern schreibst du trotzdem.

Aus der Beschreibung wird so eine Zeile in main:

objekt.methode(werte): Methoden am Objekt aufrufen

Die Methoden aus einer Beschreibung rufst du an einem Objekt auf. Vor den Punkt kommt die Variable, die auf das Objekt zeigt. Der Punkt heißt: Dieses Objekt soll die Methode ausführen.

bikeDas ObjektDie Variable, die auf das Rad zeigt. Nicht der Klassenname Bike.
.drivePunkt und MethodeWas das Objekt tun soll.
(10)Die WerteWas die Methode bekommt, in der Reihenfolge aus der Beschreibung.

Lass das Rad bike fahren (.drive), und zwar 10 Minuten.

Gibt die Methode etwas zurück, musst du mit dem Rückgabewert etwas tun: ihn ausgeben oder in einer Variable speichern. Sonst verpufft er. Das zeigt der erste Lauf. In den Läufen steht der Code der Klassen ohne final, damit er kürzer ist.

Zeile 4 läuft zwar, aber niemand fängt den Text auf. Erst Zeile 5 gibt ihn aus. Gibt dein Programm nichts aus, obwohl du eine Methode aufgerufen hast? Schau dann nach, ob System.out.println(…) drumherum fehlt.

Ein Objekt an ein anderes übergeben

Jetzt kommt die zweite Klasse dazu. Die Station hat einen Namen und eine Zahl von Plätzen. Ihre Methode addBike bekommt als Wert keinen Text und keine Zahl, sondern ein ganzes Rad:

Klasse Station (Ausschnitt)

  • Station(final String name, final int capacity): Ein Konstruktor, um eine neue, leere Station mit dem gegebenen Namen und der gegebenen Zahl von Plätzen zu erzeugen.
  • void addBike(final Bike bike): Stellt ein Rad an die Station.
  • String getInfo(): Gibt einen Text mit dem Namen und der Zahl der belegten Plätze zurück.

Bei addBike(final Bike bike) ist der Typ des Parameters Bike. Also schreibst du in die Klammern eine Variable, die auf ein Rad zeigt: station.addBike(bike);. Die Methode bekommt dabei keine Kopie des Rads, sondern einen Pfeil auf dieselbe Karte. Wähl im Lauf aus, ob ein Rad oder zwei Räder dazukommen.

Achte im Lauf auf die Karte der Station. Ihr Attribut lastBike zeigt am Ende auf ein Rad. Ein Objekt kann also über ein Attribut auf ein anderes Objekt zeigen.

Vorher, nachher und die Differenz

Eine typische Aufgabe lautet: Lass etwas passieren und gib aus, wie stark sich ein Wert dabei geändert hat. Dafür kommt die dritte Klasse dazu:

Klasse Rider (Ausschnitt)

  • Rider(final String name, final int credit): Ein Konstruktor, um eine neue Person mit dem gegebenen Namen und Guthaben in Cent zu erzeugen.
  • void ride(final Bike bike, final int minutes): Fährt mit dem gegebenen Rad. Das Rad verliert 1 Prozent Akku pro Minute, das Guthaben sinkt um 10 Cent pro Minute.

Der Trick: Java merkt sich alte Werte nicht von selbst. Wenn du den Akkustand vor der Fahrt brauchst, musst du ihn vor der Fahrt in einer Variable speichern. Das Muster hat immer vier Schritte:

  1. Vorher-Wert mit dem Getter holen und in einer Variable speichern: int before = bike.getBattery();
  2. Die Aktion ausführen: rider.ride(bike, 12);
  3. Nachher-Wert holen: int after = bike.getBattery();
  4. Differenz rechnen und mit Text ausgeben: int used = before - after; und dann System.out.println("Akkuverbrauch: " + used);

Vergleich im Lauf zwei Fassungen: Einmal speicherst du before vor der Fahrt, einmal erst danach. Achte auch darauf, wo sich der Akku ändert. ride läuft in Rider.java, aber es ändert die Karte des Rads, und main sieht die Änderung.

In der falschen Fassung haben before und after denselben Wert. Die Differenz ist 0, obwohl das Rad gefahren ist. Gibt dein Programm bei einer Differenz 0 aus? Prüf dann zuerst die Reihenfolge.

Sechs Regeln zum Merken

  1. Lies zuerst die Beschreibung: Was braucht der Konstruktor, in welcher Reihenfolge? final überliest du.
  2. Ein Objekt erzeugst du mit Typ name = new Typ(werte);. Die Werte kommen in der Reihenfolge der Parameter.
  3. Die Methoden aus einer Beschreibung rufst du am Objekt auf: bike.getBattery(). Vor den Punkt gehört die Variable, nicht der Klassenname.
  4. Steht vor der Methode ein Typ, kommt ein Wert zurück. Speichere ihn (int x = …;) oder gib ihn aus (System.out.println(…);). Bei void kommt nichts zurück.
  5. Übergibst du ein Objekt, bekommt die Methode einen Pfeil auf dieselbe Karte. Ändert sie das Objekt, sieht main die Änderung.
  6. Vorher merken, Aktion, nachher holen, Differenz rechnen. Genau in dieser Reihenfolge.
