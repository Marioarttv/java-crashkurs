Das solltest du schon kennen: Klasse, Objekt, Konstruktor, new und Getter (Methoden, die ein Attribut zurückgeben) aus Kapitel 4, Rückgabewerte aus Kapitel 3 sowie Rechnen mit / und % aus Kapitel 2.

In Kapitel 4 hast du Klassen selbst geschrieben. Oft ist es umgekehrt: Jemand anderes hat die Klassen schon geschrieben. Du bekommst eine Beschreibung und benutzt die Klassen in deinem eigenen Code.

Das ist wie bei einem Fahrradverleih-Automaten. Du musst nicht wissen, wie er innen funktioniert. Es reicht, wenn du weißt, welche Knöpfe es gibt, was du eingibst und was herauskommt. Die Beschreibung einer Klasse ist so eine Bedienungsanleitung.

Das Thema in diesem Kapitel ist ein Verleih für E-Bikes. Es gibt drei Klassen: Bike (ein Rad), Charger (eine Ladesäule) und Tariff (ein Tarif, der Preise ausrechnet). Du lernst sie nacheinander kennen.

Eine Beschreibung lesen

Eine solche Beschreibung sieht zum Beispiel so aus. Lies sie einmal ganz durch:

Klasse Bike

Ein Objekt der Klasse Bike ist ein E-Bike. Es kennt seine Nummer (number) und seinen Akkustand in Prozent (battery).

  • Bike(final String number, final int battery): erzeugt ein Rad mit dieser Nummer und diesem Akkustand.
  • String getNumber(): gibt die Nummer zurück.
  • int getBattery(): gibt den Akkustand in Prozent zurück.
  • int getRange(): gibt die Reichweite in ganzen Kilometern zurück. Für einen Kilometer braucht das Rad 2 Prozent Akku.
  • void charge(final int percent): lädt den Akku um so viele Prozent auf.

Das Wichtigste steht in den Zeilen mit Code. Du liest sie wie einen Steckbrief. Fang mit dem Konstruktor an. Du erkennst ihn daran, dass er genauso heißt wie die Klasse und vorn kein Rückgabetyp steht (also kein Typ für einen Rückgabewert):

BikeName wie die KlasseDas ist ein Konstruktor. Du rufst ihn mit new Bike(…) auf.
(String …, int …)Was er brauchtErst einen Text (die Nummer), dann eine Zahl (den Akkustand). Genau in dieser Reihenfolge.
finalDarfst du überlesenfinal heißt nur: Der Konstruktor ändert diesen Parameter nicht. Für deinen Aufruf ändert sich nichts.

Der Konstruktor von Bike braucht einen Text und dann eine Zahl. Also schreibst du: new Bike("B-12", 80).

Bei den Methoden steht vorn der Rückgabetyp. Er sagt dir, was zurückkommt:

intWas zurückkommtEine Zahl. Steht hier void, kommt nichts zurück.
getRangeDer NameSchreib ihn genau so, auch bei Groß- und Kleinbuchstaben.
()Was sie bekommtHier keinen Wert. Die Klammern schreibst du trotzdem.

So wird aus einer Zeile der Beschreibung eine Anweisung in main:

In der BeschreibungBedeutungIn main schreibst du
Bike(final String number, final int battery)ein Konstruktor: erst ein Text, dann eine ZahlBike bike = new Bike("B-12", 80);
int getRange()gibt eine Zahl zurück, bekommt keinen Wertint km = bike.getRange();
void charge(final int percent)gibt nichts zurück, bekommt eine Zahlbike.charge(20);
String getNumber()gibt einen Text zurück, bekommt keinen WertSystem.out.println(bike.getNumber());

objekt.methode(werte): Methoden am Objekt aufrufen

Die Methoden aus einer Beschreibung rufst du an einem Objekt auf. Vor den Punkt kommt die Variable, die auf das Objekt zeigt. Der Punkt heißt: Dieses Objekt soll die Methode ausführen.

bikeDas ObjektDie Variable, die auf das Rad zeigt. Nicht der Klassenname Bike.
.chargePunkt und MethodeWas das Objekt tun soll.
(20)Die WerteWas die Methode bekommt, in der Reihenfolge aus der Beschreibung.

Lade das Rad bike auf (.charge), und zwar um 20 Prozent.

Gibt die Methode etwas zurück, brauchst du eine Verwendung für den Rückgabewert: Du speicherst ihn in einer Variable, gibst ihn aus oder rechnest mit ihm weiter. Sonst geht er verloren. Das zeigt der erste Lauf. In den Läufen steht der Code der Klassen ohne final und nur mit den Methoden, die der Lauf braucht.

Zeile 4 läuft zwar, aber nichts fängt die Zahl auf. Erst Zeile 5 speichert sie in km. Gibt dein Programm nichts aus, obwohl du eine Methode aufgerufen hast? Prüf dann, ob du den Rückgabewert speicherst oder ausgibst.

Ein Objekt an ein anderes übergeben

Jetzt kommt die zweite Klasse dazu: die Ladesäule. Ihre Methoden bekommen nicht nur Text oder eine Zahl, sondern ein ganzes Rad:

Klasse Charger

Ein Objekt der Klasse Charger ist eine Ladesäule. Sie weiß, um wie viel Prozent sie einen Akku pro Minute auflädt (percentPerMinute).

  • Charger(final int percentPerMinute): erzeugt eine Ladesäule, die so viele Prozent pro Minute lädt.
  • int minutesUntilFull(final Bike bike): gibt zurück, wie viele ganze Minuten das Rad laden kann, ohne über 100 Prozent zu kommen. Geht die Rechnung genau auf, ist der Akku danach voll.
  • void plugIn(final Bike bike, final int minutes): lädt das Rad so viele Minuten lang.

Bei plugIn(final Bike bike, final int minutes) hat der erste Parameter den Typ Bike. Also schreibst du an diese Stelle eine Variable, die auf ein Rad zeigt: charger.plugIn(bike, 10);. Die Methode bekommt dabei keine Kopie des Rads, sondern einen Pfeil auf dieselbe Objektkarte. Stell im Lauf ein, wie viele Minuten das Rad lädt.

Achte im Lauf auf die Objektkarte ① des Rads. In main steht keine Zeile, die den Akku ändert. Trotzdem gibt Zeile 6 den neuen Wert aus. Die Ladesäule hat über ihren Parameter bike genau das Rad geändert, auf das auch bike in main zeigt.

Den Rückgabewert weiterverwenden

Ein Rückgabewert ist ein normaler Wert. Ist er eine Zahl, kannst du mit ihm rechnen wie mit jeder anderen Zahl. Dafür kommt die dritte Klasse dazu:

Klasse Tariff

Ein Objekt der Klasse Tariff ist ein Tarif. Er kennt den Preis für das Entsperren eines Rads (unlockFee) und den Preis pro Minute (pricePerMinute), beide in Cent.

  • Tariff(final int unlockFee, final int pricePerMinute): erzeugt einen Tarif mit diesen beiden Preisen.
  • int priceFor(final int minutes): gibt den Preis einer Fahrt in Cent zurück, also einmal Entsperren und dazu jede Minute.

Im Lauf rechnet der Tarif einen Preis in Cent aus. Mit / und % aus Kapitel 2 machst du daraus Euro und Cent. Probier 10, 20 und 30 Minuten aus.

Du kannst einen Rückgabewert auch direkt in einen anderen Methodenaufruf einsetzen, ohne Variable dazwischen:

Java geht dann von innen nach außen vor. Zuerst ruft es minutesUntilFull(bike) auf. Der Rückgabewert steht danach dort, wo der innere Aufruf stand. Erst dann ruft Java plugIn mit dieser Zahl auf. Mit einer eigenen Variable wie int minutes = …; ist dein Code meist leichter zu lesen.

Noch etwas zu Werten, die sich ändern: Java merkt sich alte Werte nicht von selbst. Nach bike.charge(20); ist der alte Akkustand weg. Brauchst du ihn danach noch, speichere ihn vorher in einer Variable, zum Beispiel int oldBattery = bike.getBattery();. In oldBattery bleibt dann der alte Wert stehen, auch wenn sich das Rad später ändert.

Sechs Regeln zum Merken

  1. Lies zuerst die Beschreibung: Welche Werte braucht der Konstruktor, und in welcher Reihenfolge? final darfst du überlesen.
  2. Ein Objekt erzeugst du mit Typ name = new Typ(werte);. Die Werte kommen in der Reihenfolge der Parameter.
  3. Die Methoden aus einer Beschreibung rufst du am Objekt auf: bike.getRange(). Vor den Punkt gehört die Variable, nicht der Klassenname.
  4. Steht vor der Methode ein Rückgabetyp, gibt sie einen Wert zurück. Speichere ihn, gib ihn aus oder rechne mit ihm weiter. Bei void kommt nichts zurück. Dann kannst du auch nichts speichern oder ausgeben.
  5. Übergibst du ein Objekt, bekommt die Methode einen Pfeil auf dieselbe Objektkarte. Ändert sie das Objekt, siehst du die Änderung auch in main.
  6. Java merkt sich alte Werte nicht. Brauchst du einen früheren Wert noch, speichere ihn vor dem Aufruf, der ihn ändert.

Fünf häufige Fehler verstehen und beheben

Alle fünf Fehler unterstreicht VS Code rot. Fahr mit der Maus über die rote Stelle, dann erscheint die Meldung.
