Ein Kuchenrezept ist für 4 Personen geschrieben. Du backst aber für 6. Also rechnest du jede Zutat um: Menge mal Personen, geteilt durch 4. Damit du nicht jedes Mal neu nachdenken musst, schreibst du die Regel einmal auf eine Karteikarte: „Umrechnen: Menge mal Personen, geteilt durch 4.“

Von da an nimmst du für jede Zutat die Karte, setzt Menge und Personen ein und bekommst die neue Menge. Dann machst du im Rezept genau dort weiter, wo du warst.

In Java heißt so eine Karteikarte Methode: ein benannter Programmteil. Du schreibst ihn einmal und benutzt ihn, so oft du willst. Eine Methode kennst du schon: main. Jetzt schreibst du eigene.

Stell danach im Kasten eine andere Zahl von Personen ein.

Beim Aufruf springt Java in die Methode. Die Zeile mit dem Aufruf wartet so lange. Die Methode bekommt einen eigenen Bereich im Speicher, mit ihren Parametern und Variablen. Mit return springt Java zurück an genau die Stelle, die gewartet hat. Der Rückgabewert steht dann dort, wo vorher der Aufruf stand. Der Bereich der Methode verschwindet mit allen Variablen darin.

Methoden ohne Rückgabewert: void

Nicht jede Methode rechnet etwas aus. Manche erledigen nur eine Aufgabe, zum Beispiel eine Zeile ausgeben. Dann geben sie keinen Wert zurück. Statt eines Rückgabetyps steht vor dem Namen void. Das heißt „leer“: Die Methode gibt nichts zurück. Sie braucht deshalb auch kein return.

Die Methode printIngredient bekommt einen Text name und eine ganze Zahl grams und gibt nichts zurück.

Im nächsten Beispiel steht die Methode über main. Achte darauf, wo Java anfängt. Das Programm ruft die Methode zweimal auf, mit verschiedenen Werten.

Die Reihenfolge der Methoden in der Datei ist egal. Java beginnt immer bei main. Es springt erst in eine Methode, wenn ein Aufruf kommt. Bei jedem Aufruf bekommt sie einen neuen Bereich im Speicher mit neuen Werten.

Was mit dem Rückgabewert passiert

Gibt eine Methode etwas zurück, musst du damit etwas anfangen. Sonst ist der Wert sofort verloren. Vergleich die drei Fassungen im Kasten. Die Methode scale ist in allen gleich, nur Zeile 3 und 4 unterscheiden sich.

Du kannst den Rückgabewert in einer Variable speichern oder direkt benutzen, zum Beispiel in println. Rufst du die Methode auf, ohne den Rückgabewert zu benutzen, meldet Java keinen Fehler. Der Wert geht trotzdem verloren.

Den Methodenkopf lesen

Oft ist der Methodenkopf schon vorgegeben. Aus dem Kopf liest du ab, was die Methode bekommt, was sie zurückgibt und wie der Aufruf aussehen muss. In der Tabelle fehlt vorne jeweils public static, damit sie übersichtlich bleibt:

Methodenkopfbekommtgibt zurückpassender Aufruf
int scale(int grams, int persons)zwei ganze Zahleneine ganze Zahlint flour = scale(500, 6);
void printIngredient(String name, int grams)einen Text, dann eine ZahlnichtsprintIngredient("Mehl", 500);
String label(String name, int grams)einen Text, dann eine Zahleinen TextString line = label("Mehl", 500);

Auch main hat so einen Kopf: public static void main(String[] args). void heißt: main gibt nichts zurück. In den Klammern steht ein Parameter mit dem Namen args. Den brauchst du nicht, er muss aber da stehen. Was die eckigen Klammern bedeuten, erklärt Kapitel 10.

Sechs Regeln zum Merken

  1. Eine Methode ist ein benannter Programmteil. Definieren heißt: Kopf und Block schreiben. Aufrufen heißt: Name und Werte in Klammern, zum Beispiel scale(500, 6).
  2. Der Methodenkopf nennt Rückgabetyp, Name und Parameter: public static int scale(int grams, int persons).
  3. Beim Aufruf springt Java in die Methode, die Aufrufzeile wartet. Danach geht es an genau dieser Stelle weiter.
  4. Java verteilt die Werte beim Aufruf der Reihe nach auf die Parameter. Anzahl, Reihenfolge und Typ müssen passen.
  5. return gibt den Rückgabewert zurück und beendet die Methode. Eine void-Methode gibt nichts zurück und braucht kein return.
  6. Den Rückgabewert speicherst du in einer Variable oder benutzt ihn direkt. Java beginnt immer bei main, egal wo die Methoden in der Datei stehen.

Fünf häufige Fehler verstehen und beheben

Bei Methoden passen am häufigsten Methodenkopf und Aufruf nicht zusammen. Lies bei jeder Meldung zuerst, welche Methode gemeint ist. Vergleiche dann den Aufruf mit dem Methodenkopf.
