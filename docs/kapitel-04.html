Bauplan und Ding: Klasse und Objekt

Eine Klasse ist ein Bauplan. Sie legt fest, welche Felder jede Karte hat. Werte enthält sie selbst noch keine. Sie ist wie der leere Vordruck einer Karteikarte.

Ein Objekt ist ein Ding, das nach dem Bauplan entsteht. Es ist wie eine ausgefüllte Karte. Aus einem Bauplan kannst du beliebig viele Objekte bauen. Jedes hat seine eigenen Werte.

Die drei Zeilen in der Klasse heißen Attribute. Ein Attribut ist eine Variable, die zu einem Objekt gehört. Du schreibst es wie eine Variable aus Kapitel 2: erst der Typ, dann der Name. Attribute stehen direkt in der Klasse, außerhalb jeder Methode.

Neu ist das Wort private. Es heißt: Nur der Code in dieser Klasse darf das Attribut direkt lesen und ändern. Andere Klassen müssen das Objekt fragen. Wie das geht, zeigt der Abschnitt „Getter“ weiter unten. Schreib private vor jedes Attribut und lass es dabei.

Der Konstruktor füllt ein neues Objekt

Wenn ein neues Buch entsteht, sollen seine Attribute gleich die richtigen Werte bekommen. Das erledigt der Konstruktor. Ein Konstruktor ist ein Programmteil, der beim Bauen eines Objekts genau einmal läuft und die Attribute füllt. Er steht in der Klasse, meistens direkt unter den Attributen:

Ein Konstruktor sieht fast aus wie eine Methode aus Kapitel 3. Es gibt aber zwei Unterschiede, und beide sind wichtig:

BookHeißt wie die KlasseGenau gleich geschrieben, mit großem Anfangsbuchstaben. Daran erkennt Java den Konstruktor.
kein TypKein RückgabetypVor dem Namen steht nur public. Kein int, kein String, auch kein void.

Das dritte Attribut, borrowed, kommt im Konstruktor nicht vor. Das ist Absicht: Ein neues Buch ist noch nicht ausgeliehen. Dafür reicht der Standardwert false, also der Startwert, den Java jedem neuen Objekt von selbst gibt. Als Parameter bekommt der Konstruktor nur Werte, die bei jedem Buch anders sind.

this: links das Attribut, rechts der Parameter

Im Konstruktor gibt es zwei Dinge mit dem Namen title: das Attribut des Objekts und den Parameter. Die Zeile this.title = title; unterscheidet sie:

Speichere den Wert aus dem Parameter title im Attribut title von diesem Objekt.

this heißt „dieses Objekt“: das Objekt, um das es gerade geht. Im Konstruktor meint this das neue Objekt, das new gerade baut. this.title ist also das Attribut auf seiner Karte. title allein meint den Parameter. Wie immer bei einer Zuweisung mit = wandert der Wert von rechts nach links.

Ein Objekt bauen mit new

Ein Objekt baust du an einer anderen Stelle, zum Beispiel in main. Dafür schreibst du das Wort new. Diese eine Zeile hat vier Teile:

BookDer TypWas für ein Ding in der Variable steckt: ein Buch. Der Typ ist der Name der Klasse.
bDer NameSo heißt die Variable, über die du das Buch später erreichst.
new BooknewBaut ein neues Objekt nach dem Bauplan Book.
("Momo", 320)Die WerteGehen an den Konstruktor, in derselben Reihenfolge wie seine Parameter.

Leg eine Variable vom Typ Book mit dem Namen b an, bau ein neues Buch mit den Werten „Momo“ und 320 und lass b darauf zeigen.

Java arbeitet diese Zeile in vier Schritten ab, zuerst rechts vom =, dann links:

  1. new baut ein neues, leeres Objekt: eine Karte im Speicher. Ihre Attribute bekommen zuerst Standardwerte: 0 für Zahlen, false für boolean und null für Text und Objekte. null heißt: Hier ist noch nichts. Standardwerte bekommen nur Attribute. Eine Variable in einer Methode hat ohne Zuweisung keinen Wert. Das kennst du als Fehler „ohne Wert benutzt“ aus Kapitel 2.
  2. Java springt in den Konstruktor. Die Werte „Momo“ und 320 landen in seinen Parametern title und pages.
  3. Der Konstruktor läuft Zeile für Zeile und schreibt die Werte auf die Karte.
  4. Zurück in der Zeile mit new: Die Variable b bekommt einen Pfeil auf die Karte. In b steckt also nicht das Buch selbst, sondern der Weg zu ihm.

Getter: ein Objekt nach einem Wert fragen

Ist das Buch gebaut, kannst du Methoden an ihm aufrufen und es nach seinen Werten fragen, zum Beispiel nach seinem Titel. Das schreibst du so: b.getTitle(). Der Punkt heißt: Ruf diese Methode an dem Objekt auf, auf das b zeigt. getTitle() ist eine Methode in der Klasse Book. Sie gibt den Titel mit return zurück:

Eine Methode, die nur den Wert eines Attributs zurückgibt, heißt Getter. Ihr Name beginnt mit get, danach kommt der Name des Attributs mit großem Anfangsbuchstaben: getTitle, getPages. Bei boolean-Attributen beginnt der Name meistens mit is: isBorrowed. Weil die Attribute private sind, kommen andere Klassen nur über solche Methoden an die Werte.

Zwei Dinge sind anders als bei den Methoden in Kapitel 3:

  • Vor dem Methodennamen fehlt static. Methoden, die mit den Attributen eines Objekts arbeiten, haben kein static. Lass static hier weg. Kapitel 6 erklärt den Unterschied.
  • In getTitle steht title ohne this. davor. Das geht, weil es dort keinen Parameter mit demselben Namen gibt. Java nimmt dann von selbst das Attribut des Objekts, an dem du die Methode aufrufst.

Wenn this fehlt

Ein Fehler passiert im Konstruktor besonders oft: this. fehlt. Dann steht da title = title;. VS Code unterstreicht das nicht rot, das Programm läuft. Trotzdem stimmt das Ergebnis nicht. Vergleich die beiden Fassungen.

Ohne this. meint title auf beiden Seiten den Parameter. Der Parameter bekommt seinen eigenen Wert noch einmal. Das Attribut title auf der Karte bleibt null. Manchmal gibt ein Getter null oder 0 zurück, obwohl du bei new Werte mitgegeben hast. Schau dann zuerst in den Konstruktor.

Sechs Regeln zum Merken

  1. Eine Klasse ist ein Bauplan. Mit new baust du daraus ein Objekt. Aus einem Bauplan entstehen beliebig viele Objekte, jedes mit eigenen Werten.
  2. Attribute stehen in der Klasse außerhalb jeder Methode, mit private davor: private int pages;
  3. Der Konstruktor heißt genau wie die Klasse und hat keinen Rückgabetyp, auch kein void.
  4. Der Konstruktor läuft bei jedem new genau einmal und füllt die Attribute. Die Werte in new Book("Momo", 320) kommen in derselben Reihenfolge an wie seine Parameter.
  5. this.title = title; heißt: links das Attribut des Objekts, rechts der Parameter. Heißt der Parameter wie das Attribut, brauchst du this.. Fehlt es, behält das Attribut seinen Standardwert.
  6. b.getTitle() ruft die Methode an dem Objekt auf, auf das b zeigt. Ein Getter gibt den Wert eines Attributs zurück.

Fünf häufige Fehler verstehen und beheben

Die ersten drei Fehler unterstreicht VS Code rot. Das Programm startet dann nicht. Beim vierten zeigt VS Code nur eine gelbe Warnung, und das Programm liefert ein falsches Ergebnis. Der fünfte Fehler bricht das Programm erst beim Laufen ab. Gerade die letzten beiden solltest du kennen.
