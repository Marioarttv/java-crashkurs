Das solltest du schon kennen: Methoden mit Parametern und return (Kapitel 3), Objekte und new (Kapitel 4), static (Kapitel 6), if (Kapitel 7) und Arrays (Kapitel 10).

Am Ausgang eines Parkhauses steht ein Kassenautomat. Du steckst dein Ticket hinein. Er rechnet die Gebühr aus. Was macht er, wenn das Ticket zerknickt und nicht lesbar ist? Er rechnet nicht mit irgendeiner Zahl weiter. Er bricht den Vorgang ab und zeigt dir, warum: Ticket ungültig.

Java macht es genauso. Manchmal kann Java eine Anweisung (einen Befehl an den Computer) nicht ausführen, obwohl der Code stimmt. Zum Beispiel soll Java das vierte Fach eines Arrays lesen, das nur drei Fächer hat. Dann bricht Java an dieser Stelle ab und zeigt eine Meldung mit dem Grund. Das heißt Exception: Java bricht ab und sagt, warum.

Ein Absturz mitten im Programm

Das Programm unten merkt sich in einem Array, wie viele Plätze auf jeder Ebene des Parkhauses frei sind. Ebene 0 hat 12 freie Plätze, Ebene 1 keinen, Ebene 2 hat 7. Dann gibt es die freien Plätze der Ebene level aus.

Klick dich zuerst mit Ebene 0 durch. Stell danach Ebene 3 ein. Die gibt es nicht. Schau, welche Zeilen dann noch laufen.

Bei Ebene 3 hat das Programm „Start“ noch ausgegeben. In Zeile 6 hat Java abgebrochen. Zeile 7 lief nie, deshalb fehlt „Ende“. Das Programm stürzt also nicht am Anfang ab. Es bricht genau an der Stelle ab, an der eine Anweisung nicht geht. Alles davor ist schon gelaufen.

Die Meldung lesen

Die rote Meldung sieht am Anfang wild aus. Sie hat aber immer denselben Aufbau. Hier ist noch einmal die Meldung aus dem Beispiel:

Exception in thread "main" java.lang.ArrayIndexOutOfBoundsException: Index 3 out of bounds for length 3
	at Main.main(Main.java:6)

Du brauchst drei Stücke daraus:

ArrayIndexOutOfBoundsExceptionDie ArtDer Name der Exception. Er sagt, was für ein Problem es ist. Das Wort davor, java.lang., ist das Paket (der Ordner), in dem Java sie aufbewahrt. Das darfst du überlesen.
Index 3 out of bounds for length 3Der TextSteht hinter dem Doppelpunkt. Er sagt genauer, was los war.
at Main.main(Main.java:6)Wo es passiert istIn der Klammer stehen die Datei und die Zeile. Vor der Klammer steht die Methode: Main.main heißt „in der Methode main der Klasse Main“.

Eine ArrayIndexOutOfBoundsException ist passiert: Das Fach 3 gibt es nicht, das Array hat nur 3 Fächer (0, 1 und 2). Passiert ist es in der Datei Main.java, Zeile 6.

Die Wörter Exception in thread "main" am Anfang heißen nur „im Hauptprogramm ist eine Exception passiert“. Die stehen immer da.

Nur die Art hat hier einen Rahmen, denselben grauen Rahmen wie ein Typ (zum Beispiel int). Das hat einen Grund: Beim catch weiter unten schreibst du die Art genau an die Stelle, an der sonst ein Typ steht.

Der englische Text lässt sich Wort für Wort übersetzen: Index 3 ist die Nummer des Fachs, out of bounds heißt „außerhalb der Grenzen“, for length 3 heißt „bei Länge 3“.

Die drei häufigsten Exceptions

Diese drei Arten wirst du am häufigsten sehen. Die Meldungen darunter sind echte Meldungen von Java. Die Zeile mit at steht hier nicht dabei.

NullPointerException

Exception in thread "main" java.lang.NullPointerException: Cannot invoke "ParkingGarage.getFreeSpots()" because "garage" is null

Die Variable garage zeigt auf kein Objekt. Sie ist null. Rufst du garage.getFreeSpots() auf, fragst du also niemanden. Meist fehlt ein new (Kapitel 4). Der Text heißt übersetzt: „Kann getFreeSpots() nicht aufrufen, weil garage null ist.“

ArrayIndexOutOfBoundsException

Exception in thread "main" java.lang.ArrayIndexOutOfBoundsException: Index 3 out of bounds for length 3

Das Fach gibt es nicht. Die Fächer sind ab 0 nummeriert. Das letzte Fach hat die Nummer length - 1 (Kapitel 10). Oft steckt ein <= statt < in einer for-Schleife dahinter.

ArithmeticException

Exception in thread "main" java.lang.ArithmeticException: / by zero

Das Programm teilt eine ganze Zahl durch 0. Das geht nicht. by zero heißt „durch null“.

Abfangen mit try und catch

Ein Absturz ärgert alle, die das Programm benutzen. Weißt du vorher, an welcher Stelle etwas schiefgehen kann, dann kannst du die Exception abfangen. Das Programm läuft dann weiter. Dafür gibt es zwei Blöcke (Code zwischen geschweiften Klammern):

try„versuche“Steht vor dem Block mit dem riskanten Code.
{ ... }Der try-BlockLäuft wie gewohnt. Passiert darin eine Exception, bricht Java nur diesen Block ab.
catch„fang ab“Kommt direkt nach dem try-Block.
(ArrayIndexOutOfBoundsException e)Die ArtWelche Exception dieser Block abfängt. In e steckt danach die Exception selbst.
{ ... }Der catch-BlockLäuft nur, wenn im try-Block genau diese Art von Exception passiert ist.

Versuche, die freien Plätze auszugeben. Wenn dabei eine ArrayIndexOutOfBoundsException passiert, gib stattdessen „Ebene 3 gibt es nicht“ aus.

Probier es mit Ebene 2 und Ebene 3 aus. Achte bei Ebene 3 darauf, welche Zeile nach dem Abbruch gelb wird.

Bei Ebene 2 läuft der try-Block komplett durch. Java überspringt den catch-Block. Bei Ebene 3 springt Java mitten aus dem try-Block in den catch-Block. Alle Zeilen danach im try-Block laufen nicht mehr. Danach läuft das Programm normal weiter. Deshalb steht am Ende „Ende“ in der Ausgabe.

Selbst eine Exception werfen

Bisher hat Java die Exception ausgelöst. Du kannst das auch selbst tun. Wozu? Stell dir eine Methode vor, die die Parkgebühr ausrechnet: 2 Euro pro Stunde. Ruft jemand sie mit 0 Stunden auf, liefert sie 0 Euro. Das sieht aus wie ein echtes Ergebnis, ist aber Unsinn. Besser: Die Methode lehnt den Wert ab und meldet klar, was falsch ist.

Dafür prüft die Methode gleich am Anfang den Parameter (den Wert, den sie beim Aufruf bekommt). Ist er ungültig, wirft sie eine Exception. „Werfen“ heißt: Die Methode bricht sofort ab, und die Exception geht an die Stelle zurück, die die Methode aufgerufen hat.

throw new„wirf eine neue“new baut wie in Kapitel 4 ein Objekt, hier die Exception. throw wirft sie.
IllegalArgumentExceptionDie ArtHeißt „ungültiger Parameter“. Die passende Art, wenn ein Wert nicht erlaubt ist.
("Parkdauer muss …")Der TextDen schreibst du selbst. Er erscheint später in der Meldung.

Wirf eine neue Exception der Art IllegalArgumentException mit dem Text „Parkdauer muss mindestens 1 Stunde sein“.

Die Methode fee ist static (Kapitel 6). Sie braucht kein Parkhaus-Objekt, deshalb ruft main sie über den Klassennamen auf: ParkingGarage.fee(hours).

Achte im Beispiel auf die Farben: Die Art und der Text, die du beim throw hinschreibst, stehen hinterher genau so in der Meldung. Probier 3 Stunden, 1 Stunde und 0 Stunden aus.

Bei 0 Stunden hat die Meldung zwei Zeilen mit at. Diese Liste heißt Stacktrace (übersetzt: Spur der Aufrufe). Sie zeigt den Weg der Exception:

Exception in thread "main" java.lang.IllegalArgumentException: Parkdauer muss mindestens 1 Stunde sein
	at ParkingGarage.fee(ParkingGarage.java:4)
	at Main.main(Main.java:4)
  • Die oberste at-Zeile ist die Stelle, an der die Exception entstanden ist: ParkingGarage.java, Zeile 4, das throw.
  • Die Zeile darunter ist die Stelle, die diese Methode aufgerufen hat: Main.java, Zeile 4.

Lies einen Stacktrace deshalb von oben nach unten. Im Übungsprojekt stehen vor den Klassennamen noch die Pakete, zum Beispiel at de.phl.crashkurs.k11.ParkingGarage.fee(ParkingGarage.java:29). Wichtig sind trotzdem nur die Datei und die Zeile in der Klammer.

Werfen und abfangen zusammen

Jetzt kommen beide Teile zusammen. Die Methode fee wirft die Exception. main fängt sie mit try und catch ab und gibt den Text aus. Den Text holst du mit e.getMessage() aus der Exception. Dabei ist e ein Objekt, und seine Methode getMessage() gibt den Text zurück.

So teilen sich die beiden Methoden die Arbeit: fee erkennt den ungültigen Wert und meldet ihn. main entscheidet, was dann passiert. Hier gibt es den Text aus und macht weiter.

Exception oder rot unterstrichen?

Beides ist rot, aber es sind zwei verschiedene Dinge:

Rot unterstrichen in VS CodeException
Wann?Schon beim Schreiben, bevor das Programm startet.Erst beim Laufen, an einer bestimmten Zeile.

Kapitel 12 zeigt dir, wie du bei jeder Art von Rot vorgehst.

Sechs Regeln zum Merken

  1. Eine Exception heißt: Java bricht ab und sagt, warum. Alles vor der Zeile ist schon gelaufen, nichts danach.
  2. In der Meldung stehen die Art (der Name der Exception), der Text und in der Klammer hinter at die Datei und die Zeile.
  3. Im Stacktrace ist die oberste at-Zeile die Stelle, an der die Exception entstanden ist. Darunter steht, wer diese Methode aufgerufen hat.
  4. throw new IllegalArgumentException("Text"); wirft selbst eine Exception. Die Prüfung dafür steht am Anfang der Methode. Nach dem throw läuft in der Methode nichts mehr.
  5. try { … } catch (Art e) { … } fängt eine Exception ab. Der catch-Block läuft nur, wenn die Art passt. Danach geht das Programm normal weiter.
  6. e.getMessage() gibt den Text der Exception zurück.
