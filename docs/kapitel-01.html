Du brauchst kein Vorwissen, nur das Übungsprojekt in VS Code. Wie du es dir holst, steht auf der Startseite.

Stell dir den Aushang am Eingang der Mensa vor. Jeden Morgen schreibt ihn jemand neu, nach einer festen Liste:

  1. Schreib „Heute in der Mensa“.
  2. Schreib „Linsensuppe mit Brot“.
  3. Schreib „Kasse bis 14 Uhr“.

Die Person arbeitet die Liste von oben nach unten ab, einen Punkt nach dem anderen. Sie fragt nicht nach, ob das sinnvoll ist. Sie macht genau, was dasteht.

Ein Programm ist genau so eine Liste, nur für den Computer. Jeder Punkt der Liste heißt Anweisung: ein Befehl an den Computer. Der Computer führt die Anweisungen von oben nach unten aus.

Eine Anweisung: Text ausgeben

Deine erste Anweisung schreibt eine Zeile Text auf den Bildschirm. Das ist die Ausgabe: der Text, den das Programm anzeigt. So sieht die Anweisung aus:

Sie besteht aus vier Teilen:

System.out.printlnDer BefehlHeißt „gib eine Zeile aus“. Schreib ihn genau so, mit großem S. Das l in println ist ein kleines L.
( )Runde KlammernDarin steht, was Java ausgibt.
"Heute in der Mensa"Der TextSteht in Anführungszeichen. Java gibt ihn genau so aus, aber ohne die Anführungszeichen.
;Das SemikolonJede Anweisung endet mit einem Semikolon. Es ist der Punkt am Ende des Satzes.

Die Anführungszeichen sind wichtig. Sie zeigen Java, wo der Text anfängt und wo er aufhört. Alles dazwischen gibt Java Buchstabe für Buchstabe aus, auch Leerzeichen und Satzzeichen.

Mehrere Anweisungen: von oben nach unten

Jetzt stehen drei Anweisungen untereinander. Klick auf „Nächster Schritt“. Die gelbe Zeile ist die Zeile, die Java gerade ausführt. Unten bei „Ausgabe“ siehst du, was auf dem Bildschirm erscheint.

Wähl danach „Fassung 2“ und klick dich noch einmal durch. Dort sind zwei Zeilen vertauscht.

Jedes println beginnt eine neue Zeile in der Ausgabe. Die Reihenfolge der Ausgabe ist immer die Reihenfolge der Anweisungen. Java prüft nicht, ob das sinnvoll ist.

Die Klasse und der Dateiname

Eine Klasse ist für den Moment eine Datei mit einem Namen, in der Code steht. Was eine Klasse genau ist, erklärt Kapitel 4. Jetzt zählt nur eine Regel: Der Name hinter public class und der Dateiname sind gleich, Buchstabe für Buchstabe. Auch Groß- und Kleinschreibung muss stimmen. Beim Dateinamen steht nur .java am Ende.

Die package-Zeile und der Ordner

In VS Code siehst du links den Explorer, die Liste der Ordner und Dateien. Die Datei aus dem Beispiel liegt an dieser Stelle:

src/main/java/de/phl/crashkurs/k01/MensaBoard.java

Der Teil nach src/main/java/ ist das Paket. In der package-Zeile stehen Punkte statt Schrägstrichen: Aus dem Ordner de/phl/crashkurs/k01 wird package de.phl.crashkurs.k01;. Auch diese Zeile endet mit einem Semikolon.

Der Startpunkt main

Ein Programm startet immer bei main. Die Zeile sieht immer gleich aus:

Lerne sie auswendig, Zeichen für Zeichen: String mit großem S, eckige Klammern [] direkt dahinter, main klein. Was die einzelnen Wörter bedeuten, erfährst du nach und nach: void und die runden Klammern in Kapitel 3, static in Kapitel 6.

Blöcke und Einrückung

Ein Block ist alles zwischen einer geschweiften Klammer { und der passenden }. Blöcke stecken ineinander wie Kisten: Der Block von main steckt im Block der Klasse. Deshalb stehen am Ende zwei schließende Klammern.

Die Leerzeichen am Zeilenanfang heißen Einrückung. Java braucht sie nicht, aber du siehst damit sofort, was in welchem Block steht. VS Code rückt beim Tippen von selbst ein. Ist die Einrückung durcheinander, räumt Umschalt + Alt + F sie auf (am Mac Umschalt + Option + F).

Wo Java anfängt

Java startet nicht in der ersten Zeile der Datei. Klick dich durch und achte darauf, wo die gelbe Zeile beginnt.

Die package-Zeile und die Zeile mit public class sind keine Anweisungen. Sie sagen nur, wo die Datei liegt und wie sie heißt. Die Anweisungen in main laufen von oben nach unten.

Das Programm in VS Code starten

Jetzt startest du ein echtes Programm. Öffne dazu das Übungsprojekt in VS Code.

  1. Klick links oben auf das Symbol mit den zwei Blättern. Das ist der Explorer.
  2. Klapp die Ordner src, main, java, de, phl, crashkurs und k01 auf. Oft zeigt VS Code mehrere Ordner in einer Zeile, etwa de/phl/crashkurs. Klick dann auf MensaBoard.java.
  3. Über der Zeile mit main stehen klein die Wörter „Run | Debug“. Klick auf „Run“.
  4. Unten öffnet sich das Terminal, das Textfenster für Befehle und Ausgaben. Zuerst erscheint dort ein langer Befehl, den VS Code selbst startet. Darunter steht die Ausgabe deines Programms: Heute in der Mensa. Aufgaben nennen diesen Bereich oft die Konsole. „In der Konsole ausgeben“ heißt also: mit System.out.println ausgeben.

Siehst du kein „Run“? Dann richtet VS Code Java noch ein. Das dauert beim ersten Öffnen ein paar Minuten. Warte, bis unten in der Statusleiste nichts mehr lädt.

Fragt VS Code nach dem Klick „Build failed, do you want to continue?“, dann ist irgendwo im Projekt etwas rot unterstrichen. Klick nicht auf „Continue“. Schließ die Meldung, such die rote Stelle und behebe sie zuerst.

Speichere nach jeder Änderung mit Strg + S (am Mac Cmd + S). Ein Punkt im Reiter der Datei, oben neben ihrem Namen, heißt: noch nicht gespeichert.

Eine neue Klasse anlegen

In der Präsenzübung legst du eine Klasse selbst an, im richtigen Ordner. So geht es:

  1. Klick im Explorer mit der rechten Maustaste auf den Ordner, in den die Klasse soll, zum Beispiel k01.
  2. Wähl im Menü „New Java File“ und dann „Class...“.
  3. Oben erscheint ein Eingabefeld mit dem Hinweis „Input the class name“. Tippe den Namen der Klasse, zum Beispiel Welcome. Ohne .java, mit großem Anfangsbuchstaben. Drück Enter.
  4. VS Code legt die Datei Welcome.java an und schreibt bereits diese Zeilen hinein:
  1. Prüfe die package-Zeile. Sie muss zum Ordner passen. Steht dort etwas anderes oder fehlt sie, hast du auf den falschen Ordner geklickt. Lösch die Datei dann (Rechtsklick, „Delete“) und leg sie im richtigen Ordner neu an.
  2. Schreib zwischen die Klammern der Klasse die Zeile mit main, ihren Block und darin deine Anweisungen.

Zwei Abkürzungen helfen beim Tippen. Tippst du in der Klasse main, schlägt VS Code public static void main vor. Wählst du den Vorschlag aus, schreibt VS Code die ganze Zeile für dich. Tippst du sysout, macht VS Code daraus System.out.println();. Verlass dich nicht nur darauf: Du solltest die main-Zeile auch ohne Hilfe schreiben können.

Den ersten Test starten

Zu jeder Aufgabe im Projekt gibt es einen Test: ein Prüfprogramm, das deinen Code startet und das Ergebnis mit der Vorgabe vergleicht. Die Tests liegen in einem eigenen Ordner, src/test/java/de/phl/crashkurs/k01. Diese Dateien änderst du nicht.

  1. Öffne die Testdatei, zum Beispiel MensaBoardTest.java.
  2. Links neben der Zeile mit class MensaBoardTest steht ein kleiner grüner Pfeil. Klick darauf.
  3. Nach ein paar Sekunden steht neben dem Pfeil ein grüner Haken oder ein rotes Kreuz. Bei einem roten Test öffnet VS Code einen Kasten mit der Meldung. Sie sagt dir auf Deutsch, was noch nicht stimmt.

Alle Tests findest du auch in der Testing-Ansicht: Klick links auf das Symbol mit dem Reagenzglas. Oder du tippst den Befehl aus der Aufgabe ins Terminal (unter Windows .\gradlew.bat statt ./gradlew).

Zwei Dinge musst du dabei wissen. Erstens prüft der Test die gespeicherte Datei. Speichere deshalb vorher. Zweitens: Solange irgendwo im Projekt etwas rot unterstrichen ist, läuft im Terminal kein einziger Test, und auf grüne Tests in VS Code ist dann kein Verlass. Dann behebst du zuerst die rote Stelle. Kapitel 12 kommt darauf zurück.

Sechs Regeln zum Merken

  1. Ein Programm ist eine Liste von Anweisungen. Java führt sie von oben nach unten aus.
  2. Jede Anweisung endet mit einem Semikolon ;.
  3. System.out.println("Text"); gibt eine Zeile aus. Der Text steht in Anführungszeichen.
  4. Klassenname gleich Dateiname: public class Welcome steht in Welcome.java. Großer Anfangsbuchstabe.
  5. Die package-Zeile nennt den Ordner, mit Punkten: Aus de/phl/crashkurs/k01 wird package de.phl.crashkurs.k01;. Neue Klassen legst du mit Rechtsklick auf den richtigen Ordner an.
  6. Das Programm startet bei public static void main(String[] args) {. Jede { braucht eine }.

Fünf häufige Fehler verstehen und beheben

Wenn VS Code etwas rot unterstreicht, ist nichts kaputt. Java versteht eine Stelle im Code noch nicht und zeigt sie dir. Fahr mit der Maus über die rote Stelle, dann erscheint die Meldung. Die Meldungen sind englisch. Hier steht, was sie heißen.

Jetzt schreibst du selbst: drei Aufgaben im Projekt

Die Aufgaben liegen im Ordner src/main/java/de/phl/crashkurs/k01. Geh bei jeder Aufgabe so vor:

  1. Öffne die Datei und lies, was beim TODO steht. TODO steht in einem Kommentar: Zeilen, die mit // beginnen, ignoriert Java. Sie sind nur für Menschen.
  2. Schreib deine Anweisungen und speichere.
  3. Starte das Programm mit „Run“ und vergleiche die Ausgabe mit der Aufgabe.
  4. Starte den Test. Ist er rot, lies die Meldung.

Am Anfang sind fast alle Tests rot. Das ist normal, denn die Aufgaben sind noch nicht gelöst. Einzelne Tests können schon grün sein, bevor du etwas geschrieben hast.
